# Game development core

Treat game-development work as long-lived engineering, not as a sequence of artificially short turns. Investigate as deeply as the task requires, preserve working systems, and validate changes in the running game whenever practical.

Prefer evidence from builds, runtime logs, profiling, screenshots, controller/input tests, and reproducible gameplay states over guesses. Keep gameplay code, content/assets, editor tooling, and build/release concerns separated enough that a fix in one layer does not silently damage another.

For substantial changes, keep the current plan visible but allow implementation evidence to refine it. Record meaningful deviations instead of forcing an obsolete plan. Do not impose a fixed retry count, thinking budget, action timer, or arbitrary scope limit when the task legitimately requires broader work.
